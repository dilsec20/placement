### Q21. "What are the 4 pillars of OOPs? Explain with real-life examples"

> **1. Encapsulation** — Bundling data and methods into a single unit and restricting direct access.
> - *Example:* An ATM machine — you interact through buttons (methods) but can't directly access the vault (private data).
> ```java
> class BankAccount {
>     private double balance;          // private data
>     public double getBalance() { return balance; }  // controlled access
>     public void deposit(double amt) {
>         if (amt > 0) balance += amt;
>     }
> }
> ```
>
> **2. Inheritance** — A child class inherits properties and methods from a parent class.
> - *Example:* A Car IS-A Vehicle. Car inherits properties like speed, color from Vehicle.
> ```java
> class Vehicle { void start() { } }
> class Car extends Vehicle { void drive() { } }  // Car inherits start()
> ```
>
> **3. Polymorphism** — Same name, different behavior.
> - *Example:* The word "open" — open a door, open a book, open a file — same word, different actions.
> - **Overloading** (compile-time): `add(int,int)` and `add(double,double)` — same name, different parameters
> - **Overriding** (runtime): Child class redefines parent's method
>
> **4. Abstraction** — Hiding complex details, showing only essential features.
> - *Example:* Driving a car — you know steering wheel and pedals, but don't need to know how the engine works internally.
> ```java
> abstract class Shape { abstract double area(); }
> class Circle extends Shape {
>     double radius;
>     double area() { return Math.PI * radius * radius; }
> }
> ```

---

### Q22. "What is the difference between method overloading and overriding?"

| Feature | Overloading | Overriding |
|---------|------------|-----------|
| **When** | Compile-time (static polymorphism) | Runtime (dynamic polymorphism) |
| **Where** | Same class | Child class redefines parent's method |
| **Method signature** | Same name, DIFFERENT parameters | Same name, SAME parameters |
| **Return type** | Can be different | Must be same (or covariant) |
| **Example** | `add(int,int)` and `add(int,int,int)` | Child's `draw()` replaces Parent's `draw()` |
| **Keyword** | No special keyword | `@Override` annotation in Java |

---

### Q23. "What is the difference between abstract class and interface?"

| Feature | Abstract Class | Interface |
|---------|---------------|-----------|
| **Methods** | Can have both abstract AND concrete methods | All methods abstract (Java 8+: can have `default` methods) |
| **Variables** | Can have instance variables | Only `public static final` constants |
| **Constructor** | ✅ Can have constructors | ❌ Cannot have constructors |
| **Inheritance** | `extends` (single only) | `implements` (multiple allowed) |
| **Access modifiers** | Any access modifier | Methods are `public` by default |
| **Use when** | IS-A relationship (Animal, Vehicle) | CAN-DO capability (Flyable, Serializable) |

> *"In my Parking Lot project, I used an interface for the ParkingStrategy — different strategies (NearestFirst, FirstAvailable) implement the same interface. I used abstract concepts for the Vehicle hierarchy."*

### Q26. "What is a pointer?"

> *"A pointer is a variable that stores the memory address of another variable instead of the value itself. In C++:*
> ```cpp
> int x = 10;
> int *ptr = &x;    // ptr stores the address of x

> ```
> *Pointers are used for dynamic memory allocation, passing variables by reference, and implementing data structures like linked lists."*

### Q27. "What is the difference between stack and heap memory?"

| Stack | Heap |
|-------|------|
| Stores local variables, function calls | Stores dynamically allocated memory |
| LIFO (Last In First Out) | No specific order |
| Auto-managed (freed when function returns) | Manual (`new/delete` in C++, GC in Java) |
| Fast access | Slower access |
| Limited size (stack overflow if exceeded) | Larger, flexible size |
| Thread-specific | Shared across threads |

> ```java
> int x = 10;                    // x stored on STACK
> int[] arr = new int[100];      // arr reference on STACK, actual array on HEAP
> ```

### Q28. "What is `static` keyword?"

> *"The `static` keyword means the member belongs to the CLASS, not to any specific object.*
> - *`static` variable:* Shared across all objects. One copy in memory.
> - *`static` method:* Can be called without creating an object. `Math.sqrt(25)`.
> - *`static` block:* Runs once when class is loaded.
>
> ```java
> class Counter {
>     static int count = 0;   // shared across all objects
>     Counter() { count++; }
>     static int getCount() { return count; }  // called via Counter.getCount()
> }
> ```

### Q29. "What is `this` keyword?"

> *"`this` refers to the current object instance. It's used to:*
> 1. *Resolve ambiguity when parameter names match instance variable names*
> 2. *Call another constructor from a constructor*
> 3. *Pass current object as a parameter*
>
> ```java
> class Student {
>     String name;
>     Student(String name) {
>         this.name = name;   // this.name = instance variable, name = parameter
>     }
> }
> ```

### Q30. "What is constructor? Types of constructors?"

> *"A constructor is a special method that's called automatically when an object is created. It has the same name as the class and no return type.*
>
> **Types:**
> 1. *Default constructor — no parameters, Java provides one if you don't write any*
> 2. *Parameterized constructor — takes arguments to initialize object with specific values*
> 3. *Copy constructor — creates a new object from an existing one (common in C++)*
>
> ```java
> class Student {
>     String name;
>     Student() { name = "Unknown"; }              // default
>     Student(String name) { this.name = name; }   // parameterized
> }
> ```

### Q32. "Explain ACID properties"

> 1. **Atomicity** — "All or nothing." Either the entire transaction completes, or none of it does. If a bank transfer fails midway, both accounts are rolled back.
>
> 2. **Consistency** — The database moves from one valid state to another. All rules, constraints, and triggers are satisfied after a transaction.
>
> 3. **Isolation** — Concurrent transactions don't interfere with each other. Each transaction runs as if it's the only one executing.
>
> 4. **Durability** — Once a transaction is committed, it's permanent — even if the system crashes, the data is saved.
>
> *"In my AceCoder project, ACID is important because when a user submits code, the submission record must be created atomically — if the code execution fails, I shouldn't have a partial submission in the database."*

---

### Q33. "What is normalization? Explain 1NF, 2NF, 3NF"

> *"Normalization is the process of organizing database tables to reduce data redundancy and improve data integrity."*
>
> **1NF (First Normal Form):**
> - Each column has atomic (single, indivisible) values
> - No repeating groups
> - ❌ `skills = "Java, Python, C++"` → ✅ separate rows for each skill
>
> **2NF (Second Normal Form):**
> - Must be in 1NF
> - No partial dependency — every non-key column depends on the ENTIRE primary key
> - Only matters when you have a composite primary key
>
> **3NF (Third Normal Form):**
> - Must be in 2NF
> - No transitive dependency — non-key columns don't depend on OTHER non-key columns
> - Example: If `student_id → dept_id → dept_name`, then `dept_name` should be in a separate Departments table

---

### Q34. "What is a primary key? What is a foreign key?"

> **Primary Key:**
> - Uniquely identifies each row in a table
> - Cannot be NULL, must be unique
> - Only ONE primary key per table
> - Example: `emp_id` in Employee table
>
> **Foreign Key:**
> - A column in one table that references the primary key of another table
> - Creates a relationship between two tables
> - CAN be NULL, CAN have duplicates
> - Example: `dept_id` in Employee table references `dept_id` in Departments table
>
> *"In my AceCoder project, `user_id` is the primary key of the Users table. In the Submissions table, `user_id` is a foreign key that references Users — this way every submission is linked to a specific user."*

### Q35. "DELETE vs TRUNCATE vs DROP"

| Command | What It Does | Rollback? | Speed | WHERE clause? |
|---------|-------------|-----------|-------|--------------|
| **DELETE** | Removes specific rows | ✅ Yes | Slow (row-by-row) | ✅ Yes |
| **TRUNCATE** | Removes ALL rows, keeps table structure | ❌ No | Fast | ❌ No |
| **DROP** | Destroys the entire table (structure + data) | ❌ No | Instant | ❌ No |

> ```sql
> DELETE FROM Employee WHERE dept_id = 5;   -- removes only dept 5 employees
> TRUNCATE TABLE Employee;                   -- removes ALL rows, table exists but empty
> DROP TABLE Employee;                       -- table is completely gone
> ```

### Q40. "WHERE vs HAVING?"

| WHERE | HAVING |
|-------|--------|
| Filters individual ROWS | Filters GROUPS |
| Used BEFORE `GROUP BY` | Used AFTER `GROUP BY` |
| Cannot use aggregate functions | CAN use aggregate functions (COUNT, SUM, AVG) |
| Works on columns directly | Works on grouped/aggregated results |

> ```sql
> -- WHERE: filter rows before grouping
> SELECT dept_id, COUNT(*) FROM Employee WHERE salary > 50000 GROUP BY dept_id;
>
> -- HAVING: filter groups after grouping
> SELECT dept_id, COUNT(*) FROM Employee GROUP BY dept_id HAVING COUNT(*) > 5;
> ```

### Q41. "What is a JOIN? Explain types"

> *"JOIN combines rows from two or more tables based on a related column."*
>
> | Type | What It Returns |
> |------|----------------|

### Q46. "What is the difference between process and thread?"

| Process | Thread |
|---------|--------|
| Independent program with its own memory | Lightweight unit within a process |
| Has its own address space | Shares memory with other threads in same process |
| Heavier to create and switch | Lighter and faster to create |
| Communication is slower (IPC needed) | Communication is faster (shared memory) |
| One process crash doesn't affect others | One thread crash can affect all threads |
| Example: Chrome browser = process | Example: Tabs within Chrome = threads |

---

### Q47. "What is a deadlock? How do you prevent it?"

> *"A deadlock occurs when two or more processes are each waiting for the other to release a resource, creating a circular wait where none can proceed."*
>
> **4 conditions (ALL must be present):**
> 1. **Mutual Exclusion** — only one process can use a resource at a time
> 2. **Hold and Wait** — process holds one resource while waiting for another
> 3. **No Preemption** — resources can't be forcibly taken away
> 4. **Circular Wait** — A waits for B, B waits for A
>
> **Prevention:** Break any ONE of these conditions:
> - Require processes to request all resources at once (breaks Hold & Wait)
> - Allow preemption of resources (breaks No Preemption)
> - Order resources and require acquisition in order (breaks Circular Wait)

---

### Q48. "Explain multithreading. How did you handle concurrency?"

> *"Multithreading means running multiple threads simultaneously within a single process to improve performance.*
>
> *In my TinyLink project, I used Java's `AtomicLong` for thread-safe ID generation. AtomicLong uses CAS (Compare-and-Swap) operations to ensure no two threads get the same ID, avoiding race conditions without using locks.*
>
> *In my AceCoder project (Node.js), concurrency is handled differently — Node.js is single-threaded but uses the Event Loop with non-blocking I/O. Multiple users submitting code don't block each other because API calls to the code execution engine are asynchronous."*

### Q59. "What is JWT? How did you implement authentication?"

> *"JWT (JSON Web Token) is a compact, self-contained way to securely transmit information between parties as a JSON object.*

### Q68. "What is HashMap? How does it work internally?"

> *"A HashMap stores key-value pairs and provides O(1) average time for get/put operations.*
>
> **Internal working:**
> 1. When you `put(key, value)`, the key's `hashCode()` is computed
> 2. The hash is mapped to a bucket index (array position) using `hash % arraySize`
> 3. The key-value pair is stored in that bucket
> 4. If two keys map to the same bucket (**collision**), they're stored as a linked list (or Red-Black tree after Java 8 when list exceeds 8 nodes)
> 5. When you `get(key)`, same hash computation finds the bucket, then `equals()` finds the exact key
>
> | Operation | Average | Worst |
> |-----------|---------|-------|
> | get() | O(1) | O(n) |
> | put() | O(1) | O(n) |

### Q72. "What is the Event Loop in Node.js?"

> *"The Event Loop is what allows Node.js to perform non-blocking I/O operations despite being single-threaded.*
>
> **How it works:**
> 1. Synchronous code runs on the Call Stack
> 2. Async operations (DB queries, API calls, file reads) are offloaded to the system
> 3. When an async operation completes, its callback goes to the Callback Queue
> 4. The Event Loop checks: 'Is the Call Stack empty?' If yes, it pushes the next callback from the Queue to the Stack
> 5. This cycle repeats continuously
>
> *This is why my AceCoder backend can handle many concurrent users — while one user's code execution API call is processing, the server is free to handle other requests."*

### Q73. "What is the time complexity of your Fibonacci solution? Can you optimize?"

> *"The recursive Fibonacci has O(2^n) time complexity — it recalculates the same subproblems repeatedly.*
>
> **Optimization options:**
> 1. **Memoization (Top-down DP):** Store computed values in an array. O(n) time, O(n) space.
> 2. **Tabulation (Bottom-up DP):** Build the array iteratively. O(n) time, O(n) space.
> 3. **Space-optimized:** Use only two variables. O(n) time, O(1) space.
>
> ```java
> // O(1) space — best approach
> int fibonacci(int n) {
>     int a = 0, b = 1;
>     for (int i = 2; i <= n; i++) {
>         int temp = a + b;
>         a = b;
>         b = temp;
>     }
>     return b;
> }
> ```

### Q74. "What is the time complexity of detecting a loop in a linked list?"

> *"Using Floyd's Cycle Detection (slow and fast pointer): O(n) time, O(1) space.*
> ```java
> boolean hasCycle(ListNode head) {
>     ListNode slow = head, fast = head;
>     while (fast != null && fast.next != null) {
>         slow = slow.next;          // moves 1 step
>         fast = fast.next.next;     // moves 2 steps
>         if (slow == fast) return true;  // they meet = cycle exists
>     }
>     return false;                  // fast reached null = no cycle
> }
> ```
